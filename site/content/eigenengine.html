EigenEngine

A document store that the customer runs in their own environment and that AI agents can reach only through tools. The tools enforce permissions, write down every call, and let an answer be checked against the sources it came from.

The problem

Three gaps

Attribution. An AI agent's answer can cite a source that does not support it. Retrieval systems return a passage with the answer, but returning a passage does not show that the passage supports the claim. When several agents run in a chain, a wrong citation at the first step shows up only in the final output, after the intermediate steps are gone. Request logs record that a call happened; they do not record which source each claim rests on.

Control. Most deployments give the agent the user's own access, so an agent asked to summarise one contract can read every contract that user can. Access rules are set for the person, and nothing narrows them to the task the agent was given.

Memory. Each run of an agent starts from nothing. The agent either re-reads everything it might need, which costs more as the documents grow, or it works only from what the user remembered to give it. A vector index returns passages that look similar to the question; it keeps nothing of what earlier runs concluded, so the result of a run is rarely stored in a form the next run can read.

The software

What the software does

EigenEngine is a document store plus a fixed set of tools (reading, searching, writing) that an agent must go through to reach it. The store holds the organisation's documents and data, the permissions for each agent, and a record of every run. The tools enforce the permissions and write the record. Each gap above gets its answer below, in the same order.

Attribution: the record. Every tool call an agent makes is written down, with the document it touched and which part of the task it came from. Each entry carries the hash of the one before it, so a single altered entry breaks the chain, and the final hash is written out when the run ends. The answer ships with the record. Anyone holding the original sources and the record can replay the calls and confirm that the record matches them.

Attribution: verification by recomputation. When an answer can be recomputed from its sources, such as a figure recomputed from the dataset it was plotted from or a number traced back to the cell it was copied from, the verifier recomputes it and compares the two. Whether the same check can be made to work on a sentence of prose against the documents it cites is under test; that test comes before the verifier is released as a product.

Control: permission. What each agent may read and what it may do are set in the store, per document. The tools check them on every call, so the rules do not depend on the model or on the prompt.

Memory. When a document arrives, the store indexes it and the links between it and the documents already there. Every run's results and record are written back into the store. A new run rebuilds the context its task needs from the index and from earlier results instead of re-reading everything. How much this saves as the documents grow is being measured on the prototype.

Status

Where it is, October 2026

  • A working prototype is in daily use by the founder. The company's own technical documentation is written through it: one of those documents, about a hundred pages, was produced through the prototype in roughly a day, and the project's record holds about four thousand tool calls, each traceable to the conversation it came from.
  • A runnable copy of the prototype is with two independent technical reviewers chosen by the prospective investors. Their verdict is expected during October 2026.
  • There are no customers yet. First release, early 2027: the store and tools packaged for research groups whose documents are few enough to need no retrieval layer. The verifier follows as a Python library that runs inside the customer's own environment, so no documents leave it; its date depends on the prose test above. It is aimed at teams that build AI products for legal work and financial services, where an unsupported answer has to be caught before it reaches a client.
  • The company holds no security certification yet.
