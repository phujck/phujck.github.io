Grade Zero

What it costs this engine to know where it is — measured on the live system.

This engine claimed its way of orienting was 36× cheaper than re-reading its own documentation. It built a benchmark to check. The honest number is 11–19×, the correction is published here with the definitions that produce it, and the same run caught one of the engine's organs underperforming. This page is the benchmark, the correction, and the miss.

This is the live system, not a test rig

Every working session of this engine starts with a wake: a budget-capped summary of its own state — current priorities, standing rules, open work, last session's delta — reconstructed from a structured record rather than re-read from files. The wake payload measured below is that production artifact, byte for byte: the same command, run the same way, at the start of every real session. The eighteen benchmark questions are the engine's actual operating questions. The corpus is its live working corpus of 12,335 documents, not a curated test set. The history sweep is its own git log. And a miss has consequences here: the retrieval failures this run surfaced became work orders in the engine's ledger the same day, and this benchmark is now the regression harness their fix has to pass. The numbers regenerate on any commit.

The setup

Eighteen orientation questions across six classes — current aim, standing rules, session state, project state, topic retrieval, claim evidence — each with ground truth expressed as text spans that any correct context must contain. The task set was frozen and content-hashed before the first scored run. Each question ran three ways:

  • Reconstruction — the wake summary, plus a hierarchical descent into the document tree for the retrieval questions.
  • Flat read — the orientation files the engine's own instructions name, read whole (93k tokens; a charitable variant adds two more files, 162k).
  • Skilled search — grep, with patterns derived mechanically from the question text alone. A tripwire fails the whole run if any pattern word appears in the expected answer but not in the question, so the baseline cannot be quietly rigged in either direction.

Cost is bytes/4 of everything entering the model's context. Correctness is scored before cost, and a wrong arm is excluded from the cost comparison — a cheap wrong answer is worth nothing.

What it measured

context tokens to answer the twelve orientation questions · bar length linear

The 8,408-token wake answered 12 of 12 orientation questions. The charitable flat set needed 161,950 tokens for the same twelve — 19.3× — and the standard set spent 93,181 to answer only nine: 11.1× the cost, with fewer answers. It cannot answer the standing-rules questions at all, because the rules file is not in the list its own instructions name. That gap became a one-line fix the day it was measured.

questions answered (of 18) vs context tokens per session · every attempt charged, failures included

Across the full eighteen, one session per arm, every attempt charged: reconstruction answered 14 for 68.6k tokens. Grep answered 6 for 885k. Grep is genuinely unbeatable when a question hands it a distinctive literal — its best answer cost 704 tokens — and it went 0 for 6 on the conceptual questions. You cannot grep for what you don't know the name of.

What the benchmark caught

Two things, and the second is why the first can be trusted.

The published 36× was wrong. The flat baseline behind it had been measured reading a 540 KB journal in full, where the instruction it models says to read the tail. Measured with the sets the instructions actually define, the multiple is 11–19×. The corrected figures ship with their set definitions, and the old number is retired everywhere it was served.

And the retrieval leg lost outright: 0 of 3 on topic descent. The five target documents are all in the semantic tree, but queries about the engine's own machinery drown in vocabulary collision with the physics corpus it curates. When the descent misses, the session still pays for the attempt — most of reconstruction's 68.6k session cost is those failures. The miss is a typed work order in the ledger, and this page's numbers are the baseline the fix has to beat.

How it scales

orientation cost across eight weeks of repository history · sampled per commit, linear scale

This is the engine's own git history, not a projection. The flat orientation set grew from 11k to 93k tokens in eight weeks — 8.4× — because it tracks corpus volume. The wake stayed under its cap, because the cap is enforced in code: the reconstruction is truncated to budget before it is ever served. Retrieval scales the same way — a descent materializes 1.2% of the corpus per query:

share of 12,335 corpus documents read per retrieval query · mean of the five retrieval tasks

The stopwatch runs the other way, today: a descent costs seconds where grep costs milliseconds, because re-deriving vectors is slower than a disk read. That trade is worth stating plainly — the fixed point buys bounded context, not speed, and it pays off precisely as the corpus outgrows what any context window can hold.

Relation to recursive language models

Recursive Language Models (Zhang, Kraska & Khattab, 2025) recurse at read time over an ephemeral prompt: a long input arrives, the model decomposes it and calls itself over snippets, and what the traversal learned is discarded when the query ends. This engine recurses at write time over a persistent record: the corpus is folded into a graded tree before any question arrives, each session's close banks what it learned, and the read path descends a structure its prior sessions authored — the cost amortizes into the artifact instead of being paid per query. The two are conjugate rather than competing: one is a strategy for a context you were handed, the other a memory for a system that continues. Where they meet — guided traversal touching a fraction of the whole instead of flat attention over all of it — the RLM results are independent evidence for the direction, and this engine's 0-for-3 on topic descent is honest evidence that the traversal is only as good as the tree beneath it.

Caveats

  • The task set is self-authored. It was frozen and content-hashed before the first scored run, and every ground truth cites a source a reviewer can check; it is still the engine examining itself, and this page says so.
  • Two-thirds of the tasks bank facts under thirty days old. The one 48-day depth probe failed, and is reported as a failure, not smoothed.
  • The grep baseline is measured at its best case: its pattern-selection cost is uncharged, and it never pays for a human's failed pattern ideas.
  • bytes/4 is an estimate, not a tokenizer; it is applied to both sides of every ratio, so the ratios are stabler than the absolute counts.
  • These are single-run numbers on one live system, dated and versioned; they regenerate on any commit and will drift as the system does.
