0. What this file is for

The pilot ran on a self-generated dev suite because the published 100 are the only held-out set this campaign will ever have, and a harness tuned on the items it publishes has no held-out number to report. Everything that could be tuned has now been tuned — on the dev suite. This file records what the harness IS, at this instant, in hashes, so that the run which follows can be checked against it rather than trusted.

The clause it exists to answer is the one a referee asks first: what is your held-out φ?

1.1 Held-out status — what the frozen 100 have and have not touched

Amended at v2 (AM-D1). The v1 text claimed a purity the campaign's own evidence contradicts and is superseded. This is the true statement.

No arm, prompt, lens roster, allocation rule or submission rule has ever seen these items. All arm-side iteration ran on the self-generated dev suite (seed 20260804, 120 items, published-set subtracted). No answer of ours, no bin of ours and no φ of ours has ever been computed against a frozen item, because no arm output for them exists.

The frozen 100 have had exactly two prior contacts, both scorer-side, both form-only, both arm-symmetric:

  1. dev_suite.published_binary's in-memory exclusion subtraction — reads the sequences to remove them from the dev pool, writes them nowhere.
  2. The b11a threshold validation's burnt DEV stratum. b11a-3 is a frozen scorer organ of this run, and it was implemented and refined against a DEV stratum of the authors' label set — b11a_threshold.md §4: "Rule implementation may be inspected and refined against it." Rows 0..99 of seriesWithLLMs_ext.csv are byte-identical to the frozen 100 sequences (the clone's own manifest says so), and 359 of that stratum's 672 pairs sit on those rows. So the authors' published answers for 359 (model, frozen-item) pairs, and their hand labels for them, were inspected while the classifier's form predicates were being written; s1_rule.md §4.3 enumerates specific binary-slice rows by index.

Quantified, recomputed at the amendment from the label file at md5 e5db2ea0… — not transcribed. Split rule sha1("{model}#{row}").digest()[0] % 4 == 0 → DEV, fixed in b11a_threshold.md §4 (committed at eef0412) before any measurement:

stratum pairs of which on frozen rows 0..99
DEV (burnt) 672 359
EVAL (read once) 2088 1141
all labelled 2760 1500

The classifier was validated on the authors' LABELS for those rows — never on any arm's answers to them. No arm's answers existed.

The residual risk, plainly. A form predicate of b11a-3 — the PRINTS/ORDINAL discriminations, or the S-1 constant-decode gate — refined while looking at the authors' answers to these exact 100 sequences could be incidentally better fitted to the answer dialects those sequences provoke than to dialects they do not. That is a real, if narrow, form-fit to the published answer dialects. It is not nothing.

Why it is symmetric across arms, and why that is the load-bearing defence. b11a-3 is applied byte-identically to A1, A2, A3 and to the authors' released answers, in one pass (§3.5). Any residual form-fit therefore moves every arm's φ in the same direction on the same items and cancels in the difference — and every claim this run makes is a difference (A2 − A1, A2 − A3, A3 − A1, and our arms against the published baseline). For the form-fit to bias a reported number it would have to favour one arm's answer dialect over another's, and the classifier never saw any arm's dialect: it was refined against fifteen published models' dialects, none of them ours. The channel is also form-only — the classifier picks a bin, never correctness (that is sequence_exec, byte-compare) — and the acceptance gate was measured on the EVAL stratum, disjoint from the burnt DEV stratum by construction. The direction of the residual effect is unsigned; no claim is made that it favours us.

What this does not license. Reporting the frozen 100 as untouched by every part of this campaign. It licenses reporting them as untouched by every arm-side choice, with a quantified, form-only, arm-symmetric scorer-side contact disclosed on the face of the freeze and in the paper.

2. The three arms — verbatim, unchanged

Every definition_verbatim is byte-identical to the pilot's, and each carries a definition_verbatim_sha256 so a referee can diff the two files mechanically rather than by eye. No word of any arm's mechanics was rewritten for this run.

A1 — Opus 5 bare, the published protocol replicated faithfully. Bare batched published prompt, no tools, one shot, API default temperature. No system prompt, no execution, no retry, no self-check, no revision, no second turn. Whatever that single response contains is the submission.

A3 — ablation: Opus 5 plus a single execute-verify-fix pass. Propose → one executor run → at most one fix → submit. Every item whose candidate diverged, timed out, errored or produced no trace gets exactly ONE fix turn carrying its typed residue; the post-fix answer is submitted whether or not it now verifies. No second fix, no lens roster, no minimization.

A2 — Eigen-on-Opus, the genesis loop. The full §4 item-level loop. P0 = the sequence, verbatim, never edited. The frozen five-lens roster (difference-table/recurrence · closed-form · automaton/bit-rule · number-theoretic · self-referential) dispatched as sealed hypothesis-builders returning candidate models, not prose. Verify is mechanical, no model in the path, with the anti-vacuity rule. At most 4 rounds per item. Per-item ledger required: append-only, round-stamped, six-field spine, supersedes carried on withdrawals. δ and nBDM are measured and reported, never steered.

The only substitution is the item set. Where the pilot text says "the 20 pilot sequences in pilot_rank order", read "the 100 frozen items in row_index order, ids bin-000..bin-099". Batch size follows: 100, one batched call per arm-shot. Nothing else differs.

Ordering by row_index rather than by ascending nBDM is a change from the pilot and is deliberate: it is the authors' own order, it is not a function of any harness quantity, and it cannot be accused of arranging the batch to our advantage.

Allocation (AR-1) is carried FLAT — 4 rounds per item, no reallocation, no early abandonment, budget 400. The pilot bound the full run to preregister an allocated rule from the measured curve. That curve is: 20/20 closed, 34 of 80 rounds used, max 3 on any item, no item exhausting its budget. A closure prior that never observed a failure cannot calibrate an abandonment threshold. So the allocated rule is declined, explicitly. Flat spends more, never less, and cannot be accused of a threshold tuned to the run it scores.

Submission (SR-1) carried verbatim: submit for every item, always, best available bin, no selection. Abstention is not permitted and is not conservative — the incorrect bin never enters φ, so abstaining and answering wrongly both score 0. Unclosed items score zero and are named.

3. Scoring

3.1 φ

src/laplace/superarc/phi.py, N = 100, binary suite only, incorrect bin included in N — so ρ is a share of 100 and an item we fail to close costs us ρ mass rather than vanishing. Bins [correct_nonboth, correct_ordinal, correct_prints, incorrect], decade weights [1, 0.1, 0.01], δ per bin the harmonic mean of tanh(nbdm_input / nbdm_answer) — the released tst_calc, reproduced exactly. FORMULA mode only; verified programs are banked unscored.

3.2 Bootstrap — the paper's own procedure

100 resamples with replacement at s = 25/50/75/100, φ recomputed per draw, seed 20260804, 95% percentile bands, on each arm and on the paired differences A2−A1, A2−A3, A3−A1. Paired differences resample on the same index draw across arms, so the band prices item difficulty rather than re-randomizing it away.

The released cell calls np.random.seed(42) and then np.random.default_rng(), which ignores that seed — their curve is unseeded and unreproducible. Ours is seeded, and the seed is fixed here before the run. These are preregistered intervals, unlike the pilot's DEV-4 descriptive bands.

3.4 S-1, active from the start

S-1 — an answer whose load-bearing content is a constant whose digit expansion IS the sequence bins PRINTS (×1/100), not abstraction — runs on the first classification of every frozen-run answer. There is no rebin step, no before/after column, no opportunity to see a φ under one instrument and then choose the other. Preregistered in preregistration/s1_rule.md §1, written before this file. Gate 0 at L >= 8; the generative-marker escape survives decode excision; fixtures frozen with the tag.

The honest disclosure is preregistered here so it appears in the paper whatever this run returns: S-1 cost the pilot's A1 eight rows, A3 two, and A2 none. It is the largest single instrument effect in the campaign and every part of it ran toward the campaign's own claim. The defences are procedural and are the only ones available — one predicate, one threshold, fixed on the §1.3 argument before any φ was computed; two nearest-miss cases spared and enumerated; and applied unchanged to a corpus we did not write, where it reproduces the authors' own copy labels on every row they judged.

3.5 Symmetric re-scoring

The authors' released answers are re-scored with the same instrument — same classifier bytes, same S-1, same normalizer, same phi.py, same N = 100, same bootstrap seed — in the same pass that scores our arms. A comparison in which our answers meet a rule the baseline's answers never met is not a comparison.

Read this before reading that paragraph (amended at v2, AM-D2). The commitment above is FORM symmetry and nothing else. Correctness is not in it, and as v1 stood correctness was not symmetric: DEV-5 states plainly that our arms' correctness is decided mechanically — translate, execute, byte-compare against the full 12-digit sequence — while the authors' correctness is read from their -formula-correctness column, i.e. their human graders. v1 never said so here and never cross-referenced DEV-5, so §3.5 read alone claimed a symmetry the instrument did not have. The remedy is §3.6 (SCS-1). DEV-5's direction_of_bias remains unsigned and is not restated as favourable.

Corpora: RandomBinarySeriesWithLLMs.csv, and rows 0:100 of both seriesWithLLMs_ext.csv and seriesWithLLMs_ext_Aug2025.csv. Formula sheets scored; program sheets banked unscored for integrity. The authors' own hand-label columns are read to reproduce their published φ as a control, and where our classifier disagrees with their hand label, both numbers are published side by side with every disagreement enumerated. We do not silently overwrite their labels with ours.

s1_rule.md §4.3's 13 label flips (all in one column, gemini_2.5_pro-program) are a finding about the released labels, not a result of ours, and are preregistered here so they cannot be read as post-hoc.

Normalization — sequence_exec.normalize_answer, strip comments and non-semantic whitespace, canonicalize formatting — is applied identically to every arm and to every released answer.

3.6 Symmetric-correctness sensitivity — SCS-1

Added at v2 (AM-D2), before any arm ran. This is the correctness half §3.5 was missing.

The commitment. The authors' released formula answers are put through the same mechanical correctness path our arms face: the same faithful-to-text scorer-side translation DEV-5 already sanctions for our own arms' formula answers, then sequence_exec.run_candidate execution, then byte-comparison of the normalized stdout against the full 12-digit sequence literal via sequence_exec.verify_candidate. Same organ bytes, same timeout, same normalizer, same pass.

Two columns on the authors' side, never one:

column what decides it
correctness_hand the authors' own -formula-correctness cell — their human graders. Unchanged, never overwritten.
correctness_mechanical translate → execute → byte-compare, the path our arms face.

The run report shows every published-model φ BOTH ways — φ_hand beside φ_mechanical, in one table, for every published model on every corpus in §3.5, with our three arms' φ in the same table so the like-for-like column can be read down a single rule. φ_hand remains the published baseline the paper quotes; φ_mechanical is a preregistered sensitivity, not a replacement and not a relabelling. Where a published φ and its sensitivity disagree, the paper reports the delta between them beside the delta between arms, so a referee can see how much of any claimed gap is instrument.

Every (model, row) where the two columns differ is enumerated individually with the direction of the flip and the failure mode from sequence_exec.classify_divergence. A released formula whose text cannot be translated at all is reported UNTRANSLATABLE, named, and counted incorrect in φ_mechanical only — never silently dropped, and never counted against φ_hand. Every translation source is banked verbatim, exactly as DEV-5 already requires for our own arms; where the authors' program sheet supplies a program for the same row it is also run as a cross-check, mirroring the A2/A3 cross-check DEV-5 specifies for us.

Why. s1_rule.md §4.3 already records 13 errors in one released label column (gemini_2.5_pro-program — the sequence packed as an integer and read LSB-first, hand-labelled correct with print FALSE). The released labels are known to be imperfect. Without this column every published Δ in this paper rests on our arms facing a grader that, in DEV-5's own words, "neither forgives a near-miss the way a human might, nor credits a formula whose intent is right but whose text is unexecutable", while the baseline faces the human.

This changes nothing else: not our arms' correctness column, not the authors' released labels, not the classifier, S-1, φ, N or the bootstrap seed. It adds one preregistered column on the authors' side so both sides can be read under one rule.

6. Voiding conditions

From the memo, verbatim

The frozen-set discipline is a hard law. After the freeze: no lens-roster change, no threshold tune, no prompt edit, no gate fix, no scorer touch. The frozen 100 are read once — this is the clause that answers "what is your held-out φ?".

— §6, bullet 3

Grade 1 — across the campaign: after each dev run, a seam judgement over the banked ledger (which lenses earn their keep per tier; which residue classes recur; where bin promotion stalls; where the estimator disagrees with intuition), emitting lens-roster changes, B-item fixes and genesis rows on the superarc conceptric. Every one is a dev-suite operation.

— §6, bullet 2

Then the freeze: scorer, classifier, thresholds, lens roster, prompts, budget policy and submission rule recorded as a preregistration hash. Then the one run: the published 100 are touched ONCE, post-freeze, and no result from it may change the harness — a change after the freeze voids the run and re-opens it. If this proves impossible, the §7 number is labelled in-sample and T2 is dropped.

— §5, "The held-out design"

or the harness is touched after the freeze (the run is void)

— §11, NO-GO clause

Operational — this run is void if

  1. any frozen harness-organ sha256 differs at run time or scoring time from hashes.harness_organs;
  2. the prompt actually sent differs from hashes.frozen_prompt.sent_by_every_arm;
  3. the run's items.jsonl does not reproduce items_digest, or does not hold exactly 100 records, or any record carries a key outside ALLOWED_KEYS;
  4. any code other than frozen_items opens the published CSV during the run, or any arm is given the clone path or LAPLACE_SUPERARC_BENCH;
  5. an arm is run against any item outside rows 0..99 of the named CSV;
  6. a submission rule other than SR-1, or an allocation rule other than AR-1-flat, is applied;
  7. the lens roster is changed mid-run;
  8. the classifier tag at scoring time is not b11a-3, or S-1 is disabled, or any answer is binned twice under two instruments and the better φ kept;
  9. the authors' released answers are scored with any instrument other than the one that scored our arms;
  10. this preregistration is edited after it lands, in any byte, without the run being declared void and re-opened.

The governing clause

Any harness touch after this file lands voids the run. Not "invalidates a number" — voids the run, which must then be re-opened under a new freeze against items this harness has now seen, which is to say it cannot be re-run honestly at all on this suite. That is the price, and it is the price that makes the held-out claim worth anything.

Still permitted: reading, quoting and reporting the run's outputs; writing the report, the economics artifact and the paper; fixing a defect in a NON-frozen organ that no arm and no scorer invokes — with the diff stated explicitly, since the burden of proving irrelevance is ours; and declaring the run void, which is always permitted and is the honest move whenever the alternative is a quiet edit.

If a bug is found mid-run: STOP. Do not fix it. Bank the defect, the item it hit and the run state, declare the run void, and take it to him for a scope ruling. A bug fixed mid-run converts a held-out measurement into an in-sample one, and the §7 number then carries the in-sample label the memo names.

The post-run transcript audit — AUD-1

Added at v2 (AM-D5). Additive: it touches no frozen organ, no arm, no prompt and no scorer, and changes no number this run reports.

Clause 4 above forbids giving any arm the clone path or LAPLACE_SUPERARC_BENCH — but nothing mechanical enforced it. The clone sits at a readable scratchpad path and A2's lens agents are dispatched with tool access. That clause sat as honour-system beside a design that enforces ALLOWED_KEYS on write and read and re-hashes the CSV on every load. So:

After every arm has finished and before any φ is computed, every agent transcript the run produced — A1's, A3's, A2's orchestrator transcript and every dispatched lens-agent transcript — together with every banked candidate source, every per-item ledger and every tool-call record, is grepped for:

  1. the clone path — the absolute path in item_source.bench_manifest.path, its parent, and the bare directory name superarc_bench;
  2. the env name — the literal string LAPLACE_SUPERARC_BENCH;
